このスキルは，現在の diff を対象に，観点ごとに専門化したレビューエージェントを並列で起動し，結果を集約してユーザーに報告する．

# 手順

## diff の特定

- `git status --porcelain` で，コミットされていない変更の有無を確認すること
- 引数（`$ARGUMENTS`）が指定された場合，それを `git diff` の対象として優先すること
- 引数が指定されておらず，コミットされていない変更がある場合，`git diff HEAD` の結果を diff とすること
- 引数が指定されておらず，コミットされていない変更がない場合，`git diff main...HEAD` の結果を diff とすること
- diff が空の場合，「レビュー対象の差分がありません」とだけユーザーに伝え，以降の手順を行わないこと

## レビューエージェントの並列起動

次の 4 エージェントを，1 回のメッセージ内で並列に起動すること．いずれも `run_in_background: false` を指定し，全エージェントの結果が揃うまで待つこと．

| エージェント    | 観点                   |
| --------------- | ---------------------- |
| `correctness`   | 正確性・ロジック不具合 |
| `code-quality`  | コード品質・可読性     |
| `security`      | セキュリティ           |
| `test-coverage` | テストカバレッジ       |

各エージェントに渡す prompt は，手順で取得した diff のみを含めること．次の情報は伝えないこと．

- このタスクの背景・経緯，ユーザーとの会話内容
- 他のエージェントの存在や役割
- 特定の懸念点への誘導・ヒント

prompt の形式は次のとおりとすること．

```text
以下の diff をレビューし，あなたの専門観点で発見した問題を報告してください．

<diff>
{diff の内容}
</diff>
```

## 結果の走査・集約

各エージェントから返ってきた報告を，自身で次の観点から走査すること．

- diff に含まれない箇所を指摘していないか確認し，含まれる場合は除外すること
- 複数のエージェントが同じ箇所を指摘している場合，1 件に統合すること
- 深刻度（critical / major / minor）順に並び替えること

## ユーザーへの報告

集約した結果を，次の構成で報告すること．

- 観点ごとの見出し（正確性／コード品質／セキュリティ／テストカバレッジ）
- 各見出しの下に，問題がある場合はファイルパス・行番号・概要・深刻度を列挙し，ない場合は「問題なし」と記載すること
- 末尾に，対応が必要な件数など全体の総括を記載すること
