# 命名ルール

## 原則

- プロジェクト全体で命名スタイル(ケース・略称・語彙)を一貫させる
- 略語を避け，意味が明確な名前を付ける
  - 例）`activity`，`record`，`sensorDefinition` など，ドメイン用語をそのまま使う

## アンチパターン

- 無意味な接頭辞・接尾辞
- 型情報の埋め込み
- 否定形
- 同一概念に複数の語彙を混在させる

## 構文別の慣習

- 変数・関数: `camelCase`
- 型・型エイリアス・コンポーネント: `PascalCase`
- 関数・メソッド: 動詞または動詞句で始める
- クラス・型・プロパティ: 名詞または名詞句（関数を受け取る Props は [jsx.md](./jsx.md) に従う）
- ファクトリ関数: `create*` で始める
- 真偽値・型ガード: `is` / `has` / `can` / `should` で始める
- 定数（変更されない値）: `SCREAMING_SNAKE_CASE`
